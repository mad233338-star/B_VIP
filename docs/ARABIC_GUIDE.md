# B_VIP Tool — الدليل العربي المختصر

**العلامة التجارية:** بشير الفرهان · **النظام:** Windows 10 / 11 (64-bit)
هذا الدليل مختصر موجّه للفني والمدير. التفاصيل الكاملة في الأدلة الإنجليزية داخل مجلد `docs`.

---

## ١. نظرة عامة

يتكوّن النظام من ثلاثة أجزاء:

| الجزء | الوظيفة |
|---|---|
| **برنامج سطح المكتب** | واجهة الفني: فحص الأجهزة، أدوات ADB/Fastboot، التقارير، الدعم الفني، الترخيص |
| **الخادم (Backend)** | إدارة الحسابات والتراخيص والعمليات والتذاكر وسجل التدقيق |
| **قاعدة البيانات (PostgreSQL)** | تخزين كل البيانات |

الواجهة تدعم العربية والإنجليزية، ويمكن تبديل اللغة من زر اللغة في الشريط الجانبي، فينقلب
التصميم إلى الاتجاه من اليمين إلى اليسار تلقائياً. التصميم بالأسود والذهبي والأبيض.

## ٢. التثبيت

### الخادم

1. ثبّت PostgreSQL (يُفضّل الإصدار 16).
2. أنشئ قاعدة البيانات والحساب:

```powershell
psql -h 127.0.0.1 -p 5432 -U postgres -v app_password='كلمة-مرور-قوية' -f deploy\create-database.sql
```

3. ابنِ ونشر ملفات الخادم:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\publish.ps1
powershell -ExecutionPolicy Bypass -File deploy\install-backend-service.ps1 `
  -SourceDirectory .\artifacts\backend `
  -ConnectionString "Host=127.0.0.1;Port=5432;Database=b_vip;Username=b_vip_app;Password=...;Pooling=true"
```

4. يحفظ السكربت مفتاح التوقيع ومفتاح تشفير الأسرار تلقائياً، ويطبع **رمز إنشاء المدير الأول**
   مرة واحدة فقط — احتفظ به.
5. أنشئ المدير الأول:

```http
POST http://<الخادم>:5088/api/bootstrap/first-admin
{ "token": "<الرمز>", "userName": "admin", "email": "admin@example.com", "password": "<كلمة مرور قوية>" }
```

6. بعد إنشاء المدير، أوقف إنشاء المدراء من الرمز: اضبط `Bootstrap:AllowFirstAdminBootstrap`
   على `false` وأعد تشغيل الخدمة.
7. تحقّق من عمل الخادم: `GET /api/health` يجب أن يعيد `Healthy`.

### برنامج سطح المكتب

1. شغّل ملف التثبيت `B_VIP-Setup-<version>.exe` (يتطلب صلاحيات المدير).
2. ثبّت **Android platform-tools** (تحتوي `adb.exe` و`fastboot.exe`).
3. ثبّت تعريفات USB الخاصة بالماركة (سامسونج، كوالكوم، ميدياتيك، آبل).
4. من **الإعدادات** اضبط عنوان الخادم ومجلد platform-tools.

## ٣. تسجيل الدخول

- أدخل اسم المستخدم (أو البريد) وكلمة المرور.
- خمس محاولات خاطئة تُقفل الحساب 15 دقيقة.
- إن ظهرت رسالة «الخادم غير متاح» تحقّق من عنوان الخادم في الإعدادات ومن عمل الخدمة:

```powershell
Get-Service BVIPBackend
Invoke-WebRequest http://127.0.0.1:5088/api/health -UseBasicParsing
```

## ٤. العمل على جهاز

1. فعّل **خيارات المطوّر → تصحيح USB** على الهاتف ووافق على بصمة RSA.
2. افتح **مدير الأجهزة** واضغط **فحص**.
3. الحالات المهمة:
   - `device` — الجهاز جاهز.
   - `unauthorized` — اقبل الطلب على شاشة الهاتف.
   - `offline` — من **أدوات ADB** اضغط **إعادة تشغيل خادم ADB** ثم أعد التوصيل.
   - لا يظهر الجهاز — مشكلة كابل أو تعريف، راجع قسم الأعطال أدناه.
4. يحتوي مدير الأجهزة على: بطارية، تخزين، ذاكرة، شبكة، إصدار النظام، وإعادة التشغيل (نظام /
   bootloader / recovery).

### أدوات ADB

قائمة الأجهزة، فحص الاتصال، إعادة تشغيل الخادم، جمع السجل (logcat)، وتنفيذ أمر shell واحد.
كل عملية تُسجّل على الخادم بنتيجتها الحقيقية (رمز الخروج، المدة، المخرجات).

### أدوات Fastboot

قراءة المتغيرات آمنة. أما **كتابة صورة (flash)** و**مسح قسم (wipe)** فتتطلّب تأكيداً صريحاً
وتُسجّل في سجل التدقيق باسمك ورقم الجهاز. التأكد من اسم القسم والصورة قبل التنفيذ إلزامي —
خطأ واحد قد يجعل الهاتف غير قابل للإقلاع.

### وحدات الماركات

سامسونج، ميدياتيك، كوالكوم، آبل: تشخيص اتصال وإرشادات. وحدة Google تقدّم إرشادات استرداد حساب
متوافقة مع السياسات فقط.

> النظام لا يقوم بفتح حساب Google أو تجاوز حماية FRP، ولا بتغيير IMEI أو الرقم التسلسلي، ولا
> بفتح قفل الشبكة. هذه الطلبات خارج نطاق البرنامج ولم تُنفَّذ في أي طبقة.

## ٥. العمليات وحالاتها

| الحالة | المعنى |
|---|---|
| `Queued` / `Validating` | في الانتظار أو قيد التحقق |
| `Running` | الأداة تعمل الآن |
| `Completed` | نجحت ورمز الخروج مطابق لشرط النجاح |
| `Failed` | فشلت أو الشرط لم يتحقق |
| `Cancelled` | أُلغيت بطلب منك |
| `TimedOut` | تجاوزت المهلة |
| `RequiresAttention` | المخرجات غير واضحة وتحتاج قراراً بشرياً |

- يمكنك إلغاء عمليتك في أي وقت؛ ومن يملك صلاحية `operations.cancel` يمكنه إلغاء عمليات
  الآخرين.
- العملية المنتهية لا تتغيّر نتيجتها لاحقاً، حتى لو وصل تقرير متأخر من الأداة.

## ٦. التقارير

- تُنشأ تلقائياً بعد التشخيص وتُحفظ باسم حسابك فقط.
- زر **تصدير** يحفظ التقرير بصيغة JSON في `Documents\B_VIP`.
- أرفق معرّف التقرير في التذكرة ليراه فريق الدعم.

## ٧. الترخيص

- شاشة **تفعيل الترخيص** تعرض الخطة وتاريخ الانتهاء وعدد الأجهزة المستخدمة.
- **تحقق** يعيد التأكد من الخادم (يحدث تلقائياً عند الدخول).
- **تفعيل** يربط هذا الجهاز بمقعد من الترخيص، و**إلغاء التفعيل** يحرّر المقعد قبل الانتقال لجهاز
  آخر.
- عند انتهاء الترخيص أو إيقافه تتوقف العمليات فقط، وتبقى التقارير والتذاكر متاحة.

## ٨. الدعم الفني

1. **تذكرة جديدة**: اختر التصنيف واكتب العنوان والوصف، وأرفق معرّف التقرير.
2. الردود تظهر داخل التذكرة، وتصلك التحديثات في وحدة **الإشعارات**.
3. الملاحظات الداخلية للدعم لا تظهر لك.
4. عند فتح تذكرة أرسل: اسم المستخدم، اسم الجهاز، الماركة وإصدار أندرويد، نوع العملية ومعرّفها،
   والوقت الدقيق مع رمز الخطأ.

## ٩. للـمدير

- **المستخدمون**: إنشاء، تعديل، إيقاف، إعادة تفعيل، إنهاء الجلسات.
- **الأدوار والصلاحيات**: ستة أدوار جاهزة و25 صلاحية؛ لا يمكن منح صلاحية لا تملكها أنت.
- **التراخيص**: الخطط الجاهزة (تجريبي 14 يوماً، شهري، فصلي، سنوي، دائم، مخصص)، وإدارة
  التفعيلات وسجل التحقق.
- **العمليات**: مراقبة وإلغاء العمليات المعلّقة أو التي تحتاج انتباهاً.
- **التذاكر**: تعيين، تغيير الحالة، ومتابعة كل التذاكر بصلاحية `tickets.all`.
- **التدقيق**: كل عملية حساسة مسجّلة بالمستخدم والوقت وعنوان IP.
- **النسخ الاحتياطي**: يومياً عبر `deploy\backup-database.ps1` مع الاحتفاظ 30 يوماً ونسخة خارج
  الجهاز شهرياً، وتجربة استرجاع مرتين سنوياً.
- **وضع الصيانة**: يمنع العملاء من بدء أي عملية أثناء الاسترجاع، ويبقى دخول المدير وفحص الصحة
  متاحين.

### قائمة المهام الدورية

| التكرار | المهمة |
|---|---|
| يومياً | مراجعة العمليات `RequiresAttention` ومحاولات الدخول الفاشلة |
| يومياً | التأكد من `/api/health` |
| أسبوعياً | التأكد من وجود نسخ احتياطية صالحة ومراجعة التراخيص المنتهية قريباً |
| شهرياً | مراجعة الأدوار والحسابات غير المستخدمة |
| سنوياً | تدوير `Auth:SigningKey` و`Security:SecretEncryptionKey` |

## ١٠. الأعطال الشائعة

| العرض | السبب | الحل |
|---|---|---|
| الجهاز لا يظهر في ADB | كابل، تعريف، أو وضع USB | جرّب كابل آخر ومنفذ آخر، ثبّت تعريف الشركة، أعد تشغيل خادم ADB |
| `unauthorized` | لم تُقبل بصمة RSA | افتح شاشة الهاتف ووافق على الطلب |
| `offline` | خادم ADB معلّق | أدوات ADB ← إعادة تشغيل الخادم |
| رسالة `license-not-active` | الترخيص منتهٍ أو موقوف | تحقق من الترخيص أو راجع الإدارة |
| الخدمة لا تعمل | إعداد ناقص (مفتاح التوقيع أو سلسلة الاتصال) | راجع السجل `C:\ProgramData\B_VIP\logs` |
| `503` على كل الطلبات | وضع الصيانة مفعّل | أوقف الصيانة من واجهة الإدارة |
| `429` | تجاوز حد الطلبات | انتظر دقيقة ثم أعد المحاولة |

## ١١. ملفات مهمة

| الملف | المسار |
|---|---|
| سجل الخادم | `C:\ProgramData\B_VIP\logs\backend-YYYYMMDD.log` |
| بيانات الخادم والنسخ | `C:\ProgramData\B_VIP` |
| إعدادات العميل | `%APPDATA%\B_VIP\settings.json` |
| تقارير مُصدَّرة | `Documents\B_VIP` |
| أوامر النشر | `deploy\` |
| ملفات التثبيت | `artifacts\` و`dist\` |

للدعم الفني: أرفق رقم العملية (`operation id`) أو معرّف التتبع (`X-Correlation-ID`) مع وصف
المشكلة، فذلك يختصر وقت التشخيص كثيراً.
